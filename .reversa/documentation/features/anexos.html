Requisitos

Visão Geral

Gerencia o upload, preview, compressão e remoção de arquivos anexados ao formulário de OS. Suporta compressão progressiva de imagens para reduzir o tamanho antes do envio por email.

Regras de Negócio

IDRegraConfiança
RN01Máximo de 12 anexos por formulário (excedente descartado com warning)🟢 CONFIRMADO
RN02Cada anexo no máximo 8 MB (validado no envio, não no upload)🟢 CONFIRMADO
RN03Imagens ≤ 670KB (SKIP_SIZE) não são comprimidas — apenas convertidas para base64🟢 CONFIRMADO
RN04Compressão progressiva: até 10 tentativas reduzindo largura em 80%, qualidade JPEG 0.9🟢 CONFIRMADO
RN0511ª tentativa (fallback): qualidade 0.7 sem redução adicional de largura🟢 CONFIRMADO
RN06Anexos comprimidos são renomeados para {basename}_red.jpg🟢 CONFIRMADO
RN07Anexos com dirty tracking — markAttachmentsDirty() deve ser chamada após mudanças🟢 CONFIRMADO
RN08Object URLs antigas são revogadas antes de renderizar novos previews (memory leak prevention)🟢 CONFIRMADO

Algoritmo de Compressão Progressiva

compressAttachments(files): por cada file: se file.size <= SKIP_SIZE (670KB) ou não é imagem: → apenas toBase64(file), retorna { filename, content, encoding } se é imagem e > SKIP_SIZE: largura = img.naturalWidth qualidade = 0.9 para tentativa = 0..10: canvas = drawImage(img, 0, 0, largura) blob = canvas.toBlob("image/jpeg", qualidade) se blob.size <= MAX_SIZE (650KB): break // sucesso se tentativa < 10: largura *= 0.8 // reduz 80% da largura senão: qualidade = 0.7 // fallback: reduz qualidade retorna { filename: "{basename}_red.jpg", content: blobToBase64(blob), encoding: "base64" }

Decisões de Design

DecisãoConfiança
Compressão no cliente (canvas API) — sem envio para servidor🟢
Compressão progressiva: itera reduzindo largura até atingir limite🟢
Skip para arquivos pequenos (≤ 670KB)🟢
Fallback de qualidade 0.7 na 11ª tentativa🟢
Object URL revogação entre renders🟢
Dirty tracking para evitar re-serialização🟢
